TEST CASE TEMPLATE
Mobile Applications Development Project
4th Year – Test Design Submission
1. Instructions
Your test cases should be based on the project documentation you provided and the UI you 
have already created. You are designing the tests only and are not running them yet, so 
there is no Actual Result field.
• Expected results (screen names, error messages, behaviour) should match your 
project documentation and your UI.
• Each feature should have at least one positive test case and at least one negative 
test case.
• Test Case IDs must be unique and follow the format MODULE_FEATURE_NNN 
(e.g. HR_LOGIN_001).
• Write test steps as short numbered actions, one action per step.
• Do not fill in the Status field. Leave it blank; it will be completed during test 
execution.
• The Example Test Cases section is for guidance only and should not be included in 
your submission.
Field Guide
Field What to write
Test Case ID Unique ID in the format MODULE_FEATURE_NNN.
Description One sentence starting with “Verify that…” describing exactly what 
is being tested.
Test Type Positive, Negative or Boundary.
Priority High, Medium or Low, based on how critical the feature is.
Prerequisites What must be true before the test starts.
Test Data The exact values to be used. Write “None” if no data is needed.
Test Steps Numbered actions the tester performs.
Expected Result What the app should do, based on your project documentation 
and UI.
Post-conditions The state of the app or data after the test.
Status Leave blank. Not to be filled in by students.

EXAMPLE TEST CASES
For guidance only – not included in submission
These examples, based on a sample health record app (MediRecord Mobile), show the level 
of detail expected. Do not copy them into your submission.
Example 1: Successful Patient Login
Test Case ID HR_LOGIN_001
Description Verify that a registered patient can log in with a valid email and 
password.
Test Type Positive
Priority High
Prerequisites App installed; patient account already registered.
Test Data Email: patient@example.com; Password: SecurePass123
Test Steps 1. Launch the application.
2. Enter the registered email and correct password.
3. Tap the “Login” button.
Expected Result User is taken to the Patient Dashboard; the patient’s name and 
profile photo are displayed.
Post-conditions A user session is created and the patient remains logged in.
Status
Example 2: Login with Incorrect Password
Test Case ID HR_LOGIN_002
Description Verify that login fails when a registered email is entered with an 
incorrect password.
Test Type Negative
Priority High
Prerequisites App installed; patient account already registered.
Test Data Email: patient@example.com; Password: WrongPass
Test Steps 1. Launch the application.
2. Enter the registered email and an incorrect password.
3. Tap the “Login” button.
Expected Result Error message “Invalid email or password” is shown; user remains 
on the Login screen.
Post-conditions No session is created; the password field is cleared.
Status
